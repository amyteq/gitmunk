# dev-hooks

Claude Code hooks that keep an agent session from doing irreversible damage, plus a redacted audit trail. Every hook needs `python3` on `PATH`; without it the hook exits 0 and does nothing.

| Hook | Event (matcher) | Behaviour |
| --- | --- | --- |
| `guard_tool.py` | `PreToolUse` (`Bash\|Read\|Edit\|Write`) | **Denies** `sudo`, recursive deletion of `/`, `~` or absolute paths outside `/tmp`, force push (including `+` refspecs, bundled `-f` and `--mirror`), remote branch deletion (including `-d` and `--prune`), `git filter-branch`/`filter-repo`, `gh … delete`, raw disk writes, privileged containers, and reading or sending credentials (`~/.ssh`, `~/.aws`, gcloud, `gh` hosts, `.netrc`, `secrets/`, `.env.production`, `.env.test`). **Asks** before `rm` outside `/tmp` or `$TMPDIR` (an unset, relative or `/` `TMPDIR` is not a temp root), `rmdir`, `find -delete`, `git clean`, `supabase db push/reset`, destructive SQL and `docker compose down -v`. |
| `guard_pr_merge.py` | `PreToolUse` (`Bash`) | Blocks `gh pr merge` when the PR author is not the current `gh` user, resolving the same number, URL or branch and `-R`/`--repo`/`GH_REPO` repository the CLI would act on. Also blocks two merges in one command, a `$` or backtick anywhere in a merge command, and a number or branch without `--repo` after `cd`, `pushd`, `export` or a `GH_REPO` change. Bypass a deliberate case with `ALLOW_FOREIGN_MERGE=1`. |
| `audit_event.py` | `PostToolUse` (`Bash\|Edit\|Write`), `ConfigChange` (`project_settings\|skills`) | Appends one JSON line per event to `.claude/audit/events-YYYYMMDD.log` in the project: event, session, tool, the file path or the Bash executable name when it is a literal word. The folder ignores itself with its own `.gitignore`. Command arguments, file contents and secret values are never recorded. |

## Failure policy

A rule that matches always denies or asks. If a hook itself fails (unreadable input, a missing `gh`, a bug), it allows the call, so a guard defect never locks the session. Push, `rm`, transfer, read and merge rules read the command's words as the shell splits and unquotes them, including through `env`/`xargs`-style wrappers, `sh -c`, `eval` and substitutions, and Git's global and attached or bundled options; quoting they cannot read asks. The guards are a second line behind the sandbox and `settings.json` permissions, not a security boundary.

A substitution asks when it decides words these rules cannot see. The rule reads one simple command at a time, also inside substitutions, `sh -c`, `eval` and `trap` payloads (behind wrappers too), and heredocs a shell runs. A command asks when its program is `rm`, a transfer or read program, or `git push`, and one of its own words or redirections holds a `$(…)`, backtick or `<(…)`/`>(…)` substitution, or a variable that the command line sets while it also runs a substitution (`F=$(…); cat "$F"`). A variable or substitution in command position asks when a gated word appears in its pipeline, or anywhere when the command line also sets it. Single-quoted text and quoted heredoc bodies are data, except text another program may run, which asks with or without the read skip: quoted text holding a substitution while a gated word appears in its command (`ssh host 'cat "$(…)"'`, `ssh host cat '"$(…)"'`, `watch`, `find -exec sh -c`, an `awk` or `sed` script), a heredoc body with such text fed to anything but `cat`, `tee`, `gh` or `git` (a `python3` body may hold Markdown backticks, not `$(…)`, unless it calls a shell through `os.system`, `subprocess` and the like), a body one of those four writes when the command line also runs a shell or an interpreter (`tee run.sh <<'EOF' … EOF` then `sh run.sh`), and a substitution in an unquoted heredoc that a shell runs, which the outer shell expands inside quotes too. Only a payload the local shell runs is read as commands: `eval`, `trap` and `sh -c` behind wrappers such as `env`, not an argument or heredoc of `ssh`, `docker exec` or a program named by a variable. A wrapper option that may take the next word as its value (`xargs -I SH`, `exec -a sh`) leaves the program unclear, so no payload is read and no read skip applies; `--` ends the options. A closed `$(cat <<'TAG' … TAG)` message body is literal. Text this reading cannot parse, such as a `case` statement, keeps the whole-command rule: a gated word anywhere with a substitution anywhere asks.

Before these checks, `$NAME` and `${NAME}` resolve to the value of a standalone `NAME=value` earlier in the same top-level `;`, `&&` or newline sequence, when that value is one literal word and nothing else in the command sets, reads or names the variable; a setter's quoted or option-joined argument names it too (`export 'D=x'`, `read -aD`), and so does a quoted message value the matcher drops (`unset -m 'D*'`). A name the shell sets itself (`PWD`, `REPLY`, `_`, `RANDOM` and the like), `TMPDIR`, and every name in a command that runs `eval`, `source` or `trap`, sets a variable through an expansion, a name pattern (`unset -m 'D*'`) or a flagged `${(P)N::=…}`, or changes `IFS` stay unresolved; `$TMPDIR` keeps the hook's own value as above. Resolution trusts the shell profile not to make that variable read-only or an integer. Deny rules check the command as written and as resolved, and a protected path assigned to any variable that a read or transfer program then uses is denied.

**Sandboxed reads.** When the settings files show that the call runs sandboxed with reads of the 22 protected home and project paths denied, a read program (`cat`, `head`, `grep`, …), also behind `env`-style wrappers, whose gated words are all read programs skips the substitution ask, and quoting the hook cannot read asks only around `rm`, push or transfer words. The sandbox enforces the boundary these asks guard. `rm`, push and transfer commands, a variable or substitution in command position, text the per-command reading cannot parse, and every deny keep their checks. The install guide's [When the read skip applies](../../docs/install.md#when-the-read-skip-applies) lists the settings. The signal fails closed: a missing, unreadable or mistyped file, `dangerouslyDisableSandbox`, a hosted session, another platform, or an excluded command the call runs turns it off, and the hook reads the files only when it would otherwise ask. Its limits: it cannot see `--settings`, `--setting-sources`, `--add-dir`, `/add-dir`, server-managed settings or macOS managed preferences; it trusts Claude Code to enforce the settings it reads; and a protected name deeper in the tree, such as `app/.env.production`, is covered only by the literal deny rule, not by the 22 paths.

Quoted message bodies (`-m`, `--body`, `--title`, `--notes`) and literal heredocs whose every pipeline stage starts with a literal, unquoted `cat`, `tee`, `gh` or `git` are treated as data, so writing *about* a gated command is allowed. A heredoc piped or fed to any other program, an unquoted heredoc whose body could expand `$`, backticks or `\`, and a `$(…)` payload are still matched. `$TMPDIR` counts as a temp root only with the hook's own value and case, never when the command may change it or the value holds whitespace or a glob character.
